## 1. このドキュメントの位置づけ

設計フェーズ01〜04（全36論点）が決定し、PoC で技術的な成立性も確認できた。ここでは**何を、どの順で作るか**を決め、その過程で生じた論点37〜39を設計フェーズ05として決定した。**これで全39論点が確定し、設計フェーズは完了する。**

各設計ドキュメントに残した「実装フェーズへ持ち越す事項」21件を集約し、マイルストーンに割り当てる。実装中に増えた事項は §5 の表に足していく。

## 3. 最初に潰すべきリスク

MVP の作業に入る前に、**成立しなければ設計を選び直すことになる項目**が1つあった。
**論点38のとおり M0 と並行して着手し、解決した。**

### R1. YOLO 系を TF.js 形式に変換し、ヘッドだけを学習できる形に分解できるか

**解決済み（2026-09-05）。結果は [06 §7](./06-poc-results.md#7-r1--yolo-の-tfjs-変換とヘッド分解2026-09-05-追加)。**

| 確認したこと | 結果 |
| --- | --- |
| TF.js 形式への変換 | **成立**（YOLOv8n → GraphModel、重み 12.8 MB） |
| 推論 | **26.6 ms**（640×640 / WebGL）。P1 の coco-ssd と同等 |
| ヘッドの分離 | **成立**。検出ヘッドを外したバックボーン + ネックを別モデルとして書き出せる（重み 9.0 MB） |
| ヘッドだけの学習 | **成立**。特徴量 P5 の上に載せたヘッドで loss が下がる（1ステップ 129 ms） |

**論点33（YOLO 系の輸入）を選び直す必要はない。** 転移学習の構成は P2 / P3 と同じ形になり、
方針3 の `frozen_layers` は「どこで切って書き出すか」という**変換時の選択**として実現される。

変換ツールは [`tools/model-conversion/`](../../tools/model-conversion/README.md)（Docker）。
アプリには変換機能を持たせない（論点32）。

残る未検証は次の3件で、いずれも M5（学習）の作業に含まれる。

- 本物の検出ヘッド（DFL・タスク整合の割り当て）での学習時間（持ち越し事項#19）
- バックボーンの部分解凍（持ち越し事項#18）
- 実データでの精度

## 4. マイルストーン

### M0. 土台（外部取得ゼロの原則を最初に固定する）

論点36で「最初から閉域前提で作る」と決めたため、**後から外部依存を剥がすのではなく、最初から入れない。**

| 作業 | 備考 |
| --- | --- |
| Vite + TypeScript + React のプロジェクト構成 | [03 §4](./03-system-architecture.md#4-レイヤ構成) の5層をディレクトリに反映する |
| **外部取得を禁止する仕組み** | CDN・Webフォント・外部APIを使わない（論点36）。担保方法は論点39で決定（後述） |
| Worker のバンドル構成 | 論点19の単一 ML Worker |
| Domain Layer のエンティティ定義 | ERモデル20エンティティの型と不変条件。**`project_id` を最初から持たせる**（論点37） |
| Port のインターフェース定義 | `Repository` / `BlobStore` / `InferenceEngine` / `TrainingEngine` / `ModelLoader` / `Preprocessor` / `Postprocessor` |
| CI の外部URL検査 | 論点39。`dist/` を grep し、許可リスト外の外部URLで落とす |
| オフライン動作確認の手順 | 論点39。ネットワークを切って起動〜推論まで通ることをリリース前チェックに入れる |

**外部取得ゼロの担保は論点39で決めたとおり二段構えにする。**

- **CI での成果物 grep** — 機械的な防止線。ビルド後の実物を見るため、依存の奥に埋まった参照も拾える
- **オフライン動作確認の手順化** — 実地の検証。grep が見逃す動的に組み立てられたURLは、ここで捕まえる

CSP による実行時強制は保険として設計に残すが、MVP では入れない。

### M4. プロジェクトとクラス体系

論点37の決定により、`project_id` そのものは M0・M1 で入る。**M4 は MVP スコープ外**で、プロジェクトの管理UIとクラス体系を扱う。

| 作業 | 備考 |
| --- | --- |
| `ProjectManager` | 論点16・18。作成・切替・削除。**削除は即時削除 + 実体回収**（持ち越し事項#8 をここで決定） |
| `LabelSetManager` | 方針1。**Base Model の体系の複製と、空からの作成の両方**（持ち越し事項#1 をここで決定）。index は詰め直さない |
| `StorageQuotaService` | 論点23。**80% で警告 / 95% で取り込み停止**（持ち越し事項#11 をここで決定） |

### M5. アノテーション・データセット・転移学習・評価（実装済み）

MVP スコープ外だが、`order.txt` §3.3 の中心にある機能。R1（06 §7）の構成をそのまま製品側に持ってきた。

| 作業 | 実装 |
| --- | --- |
| `AnnotationManager` | 方針5。編集のたびに新しい版を作り、**版は全件残す**（持ち越し事項#4 の決定） |
| アノテーション編集UI | Canvas で矩形の描画・選択・移動・リサイズ。数字キーでクラス切替、Delete、Ctrl+Z、Ctrl+S |
| 推論結果からの起こし | 方針12。`source = from_detection` と `origin_target_id` を残し、status は draft |
| `DatasetManager` | 方針2。可変メンバーシップ（`dataset_members`、スキーマ版2で追加）と**明示的な凍結**（持ち越し事項#3 の決定） |
| 検出ヘッド | **YOLOv8 相当**（3スケール・DFL・タスク整合割当）。持ち越し事項#19 をここで潰した |
| `TrainingManager` | 方針3・7・13。凍結した版のみ参照。系譜（`ModelDerivation`）で親のバックボーンにつながる。失敗・中断も記録に残す |
| 複数タブの排他 | 持ち越し事項#9。Web Locks で、取れなければ即座に諦める |
| 学習済みモデルでの推論 | `ModelArtifact.format = baif_yolo_head_v1`。**バックボーンは系譜の親から辿る** |
| `EvaluationManager` | 方針4。IoU 0.5 で突き合わせ、クラス別 AP と mAP@0.5 / precision / recall |

**学習は WebGL で行う。** WebGPU バックエンドでは割当（TAL）の結果が壊れる（同じコードで、
WebGL では担当セル10件・targetScores ≤ 1、WebGPU では全8400セル・targetScores 数十万）。
推論は WebGPU のままで問題ない。原因の切り分けは持ち越し（§5 #22）。
