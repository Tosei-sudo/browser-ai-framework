## 3. 最初に潰すべきリスク

MVP の作業に入る前に、**成立しなければ設計を選び直すことになる項目**が1つある。

### R1. YOLO 系を TF.js 形式に変換し、ヘッドだけを学習できる形に分解できるか

論点33で YOLO 系の輸入を決めたが、[06 §5](./06-poc-results.md#5-p2--p3--ブラウザ内の転移学習) で確認できたのは MobileNet + 単一ボックス回帰という簡略化した構成での成立である。YOLO 系で同じことができるかは未検証。

**成立しない場合の影響:**

| 成立しない内容 | 影響 |
| --- | --- |
| TF.js 形式へ変換できない | 論点33を選び直す（MobileNet 系へ戻す、または論点32の形式固定を見直す） |
| 変換はできるがヘッドを分離できない | 転移学習の実装方針が変わる。全体を fine-tune する構成になり、[06 §5.4](./06-poc-results.md#54-検証できていないこと) の未検証領域に入る |
| 分離できるが学習が遅い | `frozen_layers`（方針3）の設計が変わる |

**MVP（推論 + 履歴）には学習が含まれないため、R1 が未解決でも MVP は進められる。** ただし解決が遅れるほど手戻りの範囲が広がるので、**MVP と並行して早期に着手する。**

## 4. マイルストーン

### M0. 土台（外部取得ゼロの原則を最初に固定する）

論点36で「最初から閉域前提で作る」と決めたため、**後から外部依存を剥がすのではなく、最初から入れない。**

| 作業 | 備考 |
| --- | --- |
| Vite + TypeScript + React のプロジェクト構成 | [03 §4](./03-system-architecture.md#4-レイヤ構成) の5層をディレクトリに反映する |
| **外部取得を禁止する仕組み** | CDN・Webフォント・外部APIを使わない。CI で検出できる形にする（後述） |
| Worker のバンドル構成 | 論点19の単一 ML Worker |
| Domain Layer のエンティティ定義 | ERモデル20エンティティの型と不変条件 |
| Port のインターフェース定義 | `Repository` / `BlobStore` / `InferenceEngine` / `TrainingEngine` / `ModelLoader` / `Preprocessor` / `Postprocessor` |

**外部取得ゼロの担保方法**は実装フェーズで詰めるが、少なくとも次を検討する。

- 依存に CDN 参照が混ざっていないかの静的チェック
- ビルド成果物に対する外部URL の grep をCIに入れる
- 開発時もネットワークを切って動作確認する手順を用意する
