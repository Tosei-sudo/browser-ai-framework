# オフライン動作確認の手順

| 項目 | 内容 |
| --- | --- |
| 目的 | 外部取得ゼロ（[論点36](../design/02-open-decisions.md#論点36--閉域環境の条件)）が実際に成立していることを、閉域へ持ち込む前に確認する |
| 根拠 | [論点39](../design/02-open-decisions.md#論点39--外部取得ゼロの担保方法)。CI の静的検査と合わせて二段構えにする |
| 実施タイミング | リリース前（配信物を閉域へ持ち込む前）。および外部ライブラリを追加・更新したとき |

## なぜ CI の検査だけでは足りないか

`app/scripts/check-no-external.mjs` は成果物の**静的な文字列**しか見られない。
実行時に組み立てられるURL（`'https://' + host + path` のような形）は検出できない。
ネットワークを遮断した状態で実際に動かすことでしか捕まえられないため、この手順を置く。

## 手順

1. 成果物を作る。

   ```
   cd app
   npm ci
   npm run build
   npm run check:no-external
   ```

2. `dist/` を静的配信する。**開発サーバー（`npm run dev`）は使わない。** モジュールの解決に
   開発サーバー自身が必要になり、配信物だけで動くかを確認できないため。

   ```
   npx --offline http-server dist -p 8080   # 事前に取得済みの任意の静的サーバーでよい
   ```

3. **ネットワークを遮断する。** 次のいずれか。

   - OS のネットワーク接続を切る（機内モード、または LAN / Wi-Fi の無効化）
   - Chrome DevTools の Network タブで Throttling を `Offline` にする

4. `http://localhost:8080` を開き、次を確認する。

   | 確認項目 | 期待 |
   | --- | --- |
   | アプリが起動する | 画面が表示され、コンソールにエラーが出ない |
   | ML Worker が起動する | バックエンド（webgpu / webgl）が表示される |
   | Base Model を読み込める | 同梱した重みから読み込める（M2 以降） |
   | 推論が完走する | 検出結果が描画される（M3 以降） |
   | 履歴が保存・再表示される | 再読み込み後も残っている（M1 以降） |

5. DevTools の Network タブを開いたまま操作し、**`localhost` 以外へのリクエストが1件も出ていないこと**を確認する。
   失敗（赤い行）も含めて0件であること。**失敗して握り潰されている外部取得は、閉域では気付けない。**

## 記録

確認した日付・ビルド・ブラウザのバージョン・結果をリリースの記録に残す。
外部リクエストが見つかった場合は、URLと発生源を突き止め、修正するか
`check-no-external.mjs` の `ALLOWED` に理由付きで追加する（後者は実行時に取得しないものに限る）。
